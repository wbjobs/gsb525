# CRDT 实时看板

零构建、零运行时依赖的四列实时看板，使用 BroadcastChannel、IndexedDB、Pointer Events 和自定义 CRDT。

## 启动

```bash
npm start
```

打开 `http://localhost:4173`，然后复制 4 个标签页。

运行自动化测试：

```bash
npm test
```

## 功能

- 固定四列：待办、准备中、进行中、已完成。
- 卡片支持新增、编辑、删除、同列排序和跨列移动。
- Pointer Events 同时支持鼠标、触控笔和触摸操作。
- 所有操作立即写入 IndexedDB，刷新或重启浏览器后不丢数据。
- BroadcastChannel 在同源标签页间实时广播操作。
- Service Worker 缓存应用外壳，断服务器后仍能打开页面。
- 顶栏提供“断开连接 / 恢复同步”，可模拟单标签页离线分区。

## CRDT 设计

- 每条操作都有全局唯一 ID 和 HLC（物理时间 + 逻辑计数 + 站点 ID）。
- IndexedDB 保存不可变操作日志和删除墓碑，而不是只保存最终快照。
- 顺序使用 Logoot 风格的分数位置，支持并发插入任意两个位置之间。
- 移动按 `movedAt` 做 Last-Writer-Wins，内容按 `contentAt` 做 LWW。
- 删除是单调墓碑，迟到的并发编辑或移动不会复活卡片。
- 同步消息携带版本向量；恢复连接后双方用 `hello/welcome` 做反熵，补齐缺失操作。
- 归约器对操作顺序不敏感，重复投递按操作 ID 去重，乱序投递也收敛到同一状态。

## 冲突结果

- 两个标签页同时拖同一张卡片：HLC 较大的移动获胜；输的一方立即应用获胜位置。
- 同时排序：分数位置天然可排序；每张卡片的移动仍由 HLC 确定单一归属。
- 编辑与移动：字段级时间戳分别处理，所以改文字不会覆盖列位置，移动也不会覆盖文字。
- 删除与编辑/移动：删除始终保留墓碑；隐藏字段可继续合并，但卡片不会重新出现。
- 离线编辑：离线期间继续写入本地日志；恢复连接后双向交换缺失日志并重放。

## 手动验收

1. 打开 4 个标签页，在任一标签页新增卡片，其他标签页应立即出现，顶栏显示同步耗时。
2. 在两个标签页同时抓住同一张卡片拖到不同列后松手，等待同步，两边列和顺序一致。
3. 在一个标签页点“断开连接”，执行新增、编辑、移动、删除；另一个标签页继续修改。
4. 点“恢复同步”，确认两边的离线新增都保留、移动和编辑正确合并、删除卡片不复活。
5. 刷新任意标签页，确认卡片、顺序和墓碑仍从 IndexedDB 恢复。
